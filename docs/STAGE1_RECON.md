## A. Solana

### 4.1 п.1 — USDC ✅
- Mainnet: `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v`, classic SPL Token, decimals 6.
- Devnet (Circle): `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU`, decimals 6. Минтить нельзя. Faucet даёт 20 USDC раз в 2 часа.
- Решение: локальные тесты и devnet идут на своём мок-минте (decimals 6, freeze authority у тестового ключа, чтобы проверить заморозку). Mainnet-сборка жёстко проверяет `EPjF…` через cargo feature.

### 4.1 п.2 — заморозка USDC ℹ️
- Freeze authority USDC: `7dGbd2QZcCKcTndnHcTL8q7SMVXAkp688NTQYwrRCrar`, SPL multisig 2-of-4 у Circle.
- У classic SPL нет permanent delegate и clawback. Circle может заморозить средства, но не забрать их.
- **Если заморожен `reserve`:** падают `buy_credits`, `settle`, `settle_many` и `redeem`. Инструкции откатываются атомарно, поэтому балансы остаются согласованными, а резервы просто истекают через `expire`.
- **Если заморожена казна:** падает `settle`, потому что USDC переводится в казну. Замена казны занимает `admin_delay`, и всё это время запросы обслуживаются бесплатно: Unspent теряет выручку, пользователи не страдают.
- Текст для `programs/SECURITY.md` готов (англ., войдёт на этапе 3).

### 4.1 п.3 — Anchor и тесты ℹ️
- **Версии:** Anchor **1.2.1** (06.10.2026), репозиторий `otter-sec/anchor`. Agave CLI **4.3.0**, Rust ≥ 1.89.
- **Формат программ:** Anchor 1.2 по умолчанию собирает sBPFv3. Ожидается, что с Agave 4.4 (ноябрь 2026) деплой и обновление программ не-v3 будут отклоняться, поэтому Anchor < 1.2 брать нельзя.
- **Тесты:** Bankrun официально deprecated, берём **LiteSVM**. TS-тесты: npm `litesvm` 1.6 (на `@solana/kit` 8) и клиент, сгенерированный Codama из IDL. Этот же клиент используют шлюз и фронт.
- **Что поменялось в 1.x:**
  - `CpiContext::new(program_id, …)`;
  - дубликаты mutable-аккаунтов запрещены, но только в типизированных полях: в `remaining_accounts` проверяем сами;
  - IDL хранится через Program Metadata;
  - `anchor test` по умолчанию запускается на Surfpool.

### 4.1 п.4 — Squads v4 ✅
- Program `SQDS4ep65T869zMMBKyuUq6aD6EgTu8psMjkvj52pCf`, одинаковый на mainnet и devnet.
- `time_lock` действует на **все** предложения мультисига: от 0 до 90 дней, отсчёт с момента набора порога. Значит, схема из двух мультисигов в брифе верна.

### 4.1 п.5 — метаданные ✅
- Metaplex `metaqbxxUerdq28cj1RbAWkYQm3ybzjb6a8bt518x1s`, вызов `createV1` (Fungible), Umi.

### 4.1 п.8 — задержка `reserve` до `confirmed` ⚠️ (замер не сделан)
- Авторитетных p50/p95 на 2026 год нет.
- Оценка: **p50 ≈ 0.6–1.5 с, p95 ≈ 2–5 с** при RPC со stake-weighted QoS и priority fee ≥ p75. Основной фактор — SWQoS RPC, priority fee почти не влияет.
- Slot на mainnet теперь 250 мс. Alpenglow активен на devnet, но **не на mainnet**, поэтому замер на devnet будет нерепрезентативным.
- Нужен замер на mainnet: около 1000 memo-транзакций, меньше 0.01 SOL. **Нужны разрешение и RPC-ключ** (Helius или Triton). Скрипт готов к написанию; предлагаю мерить перед запуском (этап 9) или раньше, если дадите ключ.

### 4.1 п.9 — вместимость `settle_many` ✅ (лучше ориентира)
- **Лимиты:** v0 — 1232 байта и **64** account locks (лимит 128 не активен). На запись нужно 2 аккаунта + 8 байт, около 74 байт.
- **v0 + ALT:** **до 12 записей** в транзакции, ограничивают байты, а не CU. Берём `SETTLE_BATCH = 10`.
- **Tx v1** (4096 байт, на mainnet с 15.09.2026): до 27 записей. Позже это можно включить без изменения программы.
- ℹ️ **Burn и перевод — по одному на пакет.** Один `burn` и один `transfer` на суммарную сумму, а не на каждую запись: это экономит CU и лимит instruction trace (64).
- ℹ️ **Повтор `UserAccount` в пакете.** Один и тот же `UserAccount` может встретиться в пакете дважды. Программа перечитывает и записывает его на каждой записи, иначе потеряется обновление. Это закрываю тестом.

### Прочее ℹ️
Рент Reservation ≈ 0.00126 SOL (рент снижается поэтапно), в программе берётся `Rent::get()`.

## B. Jupiter и DEX

### 4.1 п.6 — своп в одной транзакции с покупкой ✅
- **API:** Jupiter **Swap API v2 `GET /build`** (`api.jup.ag/swap/v2`) отдаёт отдельные инструкции и карту ALT. Ultra и `/order` скомпоновать с нашими инструкциями нельзя.
- **Режим:** только **ExactIn**, как в брифе. `buy_credits(min_out)` получает `otherAmountThreshold` (гарантированный минимум). Положительный slippage остаётся у пользователя.
- **Размер транзакции:** `maxAccounts` начинаем с 48. Если транзакция больше 1232 байт или аккаунтов больше 64, повторяем запрос с 40, потом с 32. Наши статичные аккаунты лежат в своей ALT, ALT Jupiter берутся из ответа. Лишний `createAssociatedTokenAccountIdempotent` выкидываем, если ATA уже есть.
- **Комиссии:** у `/build` комиссии Jupiter нет.
- ⚠️ **Ключ Jupiter.** Без ключа 0.5 RPS, бесплатный ключ даёт 1 RPS **на всю организацию**. Для живого сайта нужен тариф Developer ($25 в месяц, 10 RPS) и прокси на нашем сервере, чтобы ключ не уходил в браузер. Для разработки хватит бесплатного.
- **Тесты:** devnet у Jupiter нет. Сквозной тест свопа делаем на форке mainnet через **Surfpool**.

### 4.1 п.7 — DEX для пула (Q9)
- Рекомендация — **Meteora DAMM v2**: создание около 0.02 SOL, Jupiter подхватывает пул автоматически, гибкая комиссия 5–25 bps, позицию можно заблокировать.
- Для сравнения: у Raydium CPMM невозвратная комиссия 0.15 SOL, у Orca — CLMM.
- Пул нужно создать вскоре после минта: grace period Jupiter считается от возраста токена. Засеять не меньше $1–2k с каждой стороны.

## C. Anthropic

### Цены и ID моделей ✅
- Все цены брифа (5.2) точно равны прайсу Anthropic × 1.15.
- ID `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`, `claude-fable-5-1` совпадают с документацией. Сверка через `GET /v1/models` нашим ключом остаётся: **нужен ключ Anthropic** (запрос бесплатный).
- **Haiku 5.5:** порог 100k считается по `input + cache_read + cache_write` одного запроса.
- **Остальные модели:** контекст 1M без надбавок за длинный промпт, max output 128k.

### Поля usage ✅ + ℹ️
- **Поля:** `input_tokens`, `output_tokens` (включает thinking), `cache_read_input_tokens`, `cache_creation_input_tokens`, `cache_creation.{ephemeral_5m_input_tokens, ephemeral_1h_input_tokens}`, `server_tool_use.{web_search_requests, web_fetch_requests}`.
- ℹ️ **Usage в стриме:** в `message_delta` он **кумулятивный**, в том числе `input_tokens`, которые растут при серверных инструментах. Разбивки кэша 5m/1h в delta нет, её берём из `message_start`.
- ℹ️ **Ловушки — `usage.iterations`:** compaction и advisor, а также server-side fallback. Их токены не входят в верхний usage, поэтому эти поля закрываются фильтром (см. D2).

### Тип ошибки 402 ✅
`402 billing_error` существует. Формат: `{"type":"error","error":{"type":…,"message":…},"request_id":…}`.

### Веб-поиск ✅
- $10 за 1000 поисков, неудачный поиск не оплачивается.
- Версии: `web_search_20250305`, `_20260209`, `_20260318`.

### Текст отказа для неизвестного инструмента ✅
`tools.0: Input tag '<type>' found using 'type' does not match any of the expected tags: …` (HTTP 400, `invalid_request_error`). Claude Code по этому тексту повторяет запрос без инструмента. Точный текст подтверждён реальными примерами из issues, отдельный запрос не нужен.

### temperature и top_p ⚠️
Модели 5.x принимают **только `temperature = 1.0`** и `top_p ≥ 0.99`, любое другое значение даёт 400. Правило 8.8 («ограничить 0–1») сломает почти любой OpenAI-клиент: они шлют 0.7 и подобное. См. D1.

### Протокол шлюза Claude Code ✅
- Все требования 8.7 подтверждены.
- Discovery: `GET /v1/models?limit=1000`, таймаут 3 с, без редиректов. Читаются поля `id`, `display_name`, `description`.
- `HEAD /api/hello` — прогрев соединения, его можно отклонить.
- `retry-after` в целых секундах; при значении больше 60 Claude Code перестаёт повторять запрос.

### Usage & Cost Admin API ✅
- `GET /v1/organizations/usage_report/messages` и `/cost_report`.
- **Нужен Admin-ключ** `sk-ant-admin01-…`. Данные появляются примерно через 5 минут.

### 404 ✅
`/v1/messages/batches*`, `/v1/files*`, прочие `/v1/*` вне списка маршрутов.

## D. OpenRouter (Q3) ⚠️

- **Цена каталога — не потолок.** `pricing` в `/models` — цена топ-провайдера. Маршрут по умолчанию может уйти к провайдеру в 1.5–70 раз дороже.
- **Как ограничить:**
  - цены брать из `/models/{id}/endpoints`;
  - в каждом запросе передавать `provider.max_price` (USD за **1M**, а не за токен);
  - для моделей с ценой кэша или условными ценами (`overrides` по длине промпта и времени суток) дополнительно передавать `provider.only`;
  - после ответа сверять `usage.cost` с резервом.
- **Usage:** приходит всегда, есть поле `cost` (USD). В стриме — в последнем чанке перед `[DONE]`. Ошибка посреди стрима приходит как HTTP 200 с `finish_reason:"error"`.
- **Белый список полей тела.** Запрещаем:
  - поля: `provider` (ставим свой), `models`, `route`, `plugins`, `service_tier`, `prediction`, `modalities`, `preset`;
  - инструменты `openrouter:*`, `web_search*`;
  - контент `file`/PDF: платный OCR;
  - суффиксы моделей `:online` `:nitro` `:floor` `:exacto` `:free` `:batch` и модели `openrouter/*`, `~*`;
  - модели Claude (`anthropic/*`, `~anthropic/*`).
- **Комиссия при пополнении:** 5.5% картой, 5% криптой. Наценки 15% хватает.
- **Сверка:** `/api/v1/activity` с management-ключом.
- **Рекомендация: на старте OpenRouter выключен**, как и предложено в Q3. Модуль делаем отдельным этапом после запуска: это заметный объём кода и рисков.
